## 2. Latency — a non-issue everywhere measured

The 25 owner queries under the query prompt; per-query cost from the (100-query −
1-query) wall-clock slope, best of three, one model load:

| config | cold (process + load + 1 query) | per-query, warm |
|---|---|---|
| Metal (M-class — desktop and M-iPads) | 354 ms | **2.5 ms** |
| CPU only, 8 threads | 389 ms | 6.0 ms |
| CPU only, 2 threads (crude A-series proxy) | 389 ms | **10.5 ms** |

With the funnel's measured 2.44 ms on top, warm typed-query semantic search lands at
**~5 ms end-to-end on M-class and ~13 ms at the pessimistic proxy** — under one frame.
Cold start is ~0.4 s once per load. The A-series proxy is crude (M-class cores throttled
by count, not A12 cores); the true floor number still wants a hardware point, but the
margin is ~10× before it would matter.

## 3. Memory — the one number that demands design, not doubt

Peak over the 25-query CLI run: **RSS 861 MB / peak footprint ~639 MB** (Metal), ~1.09 GB
RSS CPU-only — **identical with `--no-warmup`**, so this is the CLI harness's load
pattern (full weight touch + JSON accumulation), not an app-shape number. Read it as a
**ceiling, not a prediction**: the in-app integration (mmap, no stdout dump, encode →
unload) gets its own measurement in s2. Even at the measured ceiling it fits 4 GB
devices comfortably; at the 3 GB iPadOS-26 floor it dictates the shape the assessment
already required — load on demand, encode, release promptly — and if s2's in-app number
stays near this ceiling, the floor tier becomes gate-or-disclose. This is now step 4's
only open engineering question, and it is a tuning question, not a viability one.

## 4. Binary cost — revised up, still small

Release arm64 libraries the app would embed: `libllama` 3.1 MB + ggml (base/cpu/metal/
blas) ≈ 3.8 MB → **~7 MB**, against the assessment's 2–4 MB [I] estimate.
(`libllama-common` at 4.9 MB is CLI-side and not needed in-app.)

## 5. Verdict

**Go, on every axis the spike could measure.** Parity is exact for practical purposes,
latency is negligible on every tier, binary cost is ~7 MB, and memory is a bounded
design obligation rather than a risk. What remains before anything ships is unchanged
from the assessment: the owner's formal Gemma licence read, and s2's in-app memory
measurement riding the integration itself. The 229 MB opt-in download and the
narrow-first surface (semantic results on zero lexical hits) stand as designed.
