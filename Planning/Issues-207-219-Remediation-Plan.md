**E. The consolidated docs pass must produce a *tight, paste-ready* per-platform block for build 31 that summarizes all shipped changes and still fits under 4,000.

**G. ### #217 — Scope of archival neighbors · L · both
- **Goal:** add a user-selectable **scope** (volume / subseries / all indexed) to the already-reusable Archival Neighbors view, with the default keyed to trigger context, and a hard guarantee that a given scope yields the **same neighbor set/count regardless of which surface opened it**.

(3) add a scope `Picker` to `ArchivalNeighborsContent`, re-run `load` on change; extend the Codable `ArchivalNeighborsRequest` with anchor volume id + default scope for macOS window restore. (4) defaults per trigger: `init(volumeSource:)` → `.volume(anchor)` (offer expand-to-subseries/all); document/Source-Explorer inits → `.allIndexed` (offer narrow-to-volume/subseries). **(5) THE CRUX — reconcile the two divergent paths (DECIDED 2026-07-07):** today `archivalNeighbors(forLotFile:)` (volume-source) does **not** self-exclude and **adds** the Phase-4 `aliasNeighbors:4840` fallback, while the document path re-parses `raw_text` and **self-excludes** the anchor (`IndexingPipelineTests:1006-1016` proves `forLotFile`→{d1,d2} vs `forVolumeId d1`→{d2}). **Canonical policy = "exclude self (others only), alias uniform":** `neighbors(collection, scope, anchorDoc?) = { documents whose source note resolves to the collection — key-derivation AND the alias fallback applied identically on BOTH paths — within scope } − { anchorDoc if present }`. ## 5. Repeatable session workflow (applies the adversarial review)

Each issue session runs this loop. Because ultracode is on, the adversarial review is a **multi-agent refute-pass** driven by that issue's checklist in §4.

1. **Reproduce & confirm** the root cause on the real code (the §4 dossiers already pin it; re-confirm against current `v2` tip before editing).
2. **Branch** off `v2` (e.g. `claude/issue-213-collections-default`). One issue per branch/PR.
3. **Implement** the fix per the dossier, honoring the standing rules (§2.G).
4. **Build + targeted tests** — build the relevant scheme(s); run the named test target(s); compare any red against the pre-existing-failures list.
5. **Adversarial review (workflow):** implement → spawn N independent reviewer agents, each assigned a slice of the issue's *adversarial-review checklist* and prompted to **refute** that the fix is correct/complete (default to "defect" when uncertain) → collate confirmed defects → apply fixes → re-verify. Cross-platform issues get at least one reviewer per platform.
6. **Verify end-to-end** — for anything with runtime surface, drive the actual flow (simulator / macOS app), not just tests (the `verify` skill). Capture before/after evidence for UI issues (219, 207, 209, 218).
7. **Targeted docs** — apply the dossier's doc touch inline (manual sections; `[SCREENSHOT]` placeholders for the user to capture — never auto-capture).
8. **PR → review → merge to `v2`.**
9. **Close the issue:** `gh issue close <n> --comment "Fixed in <PR link>: <one-line what changed>."`
10. **Log** the session in `Planning/DEVELOPMENT-PLAN.md`.

**Parallelization:** waves 0–2 touch disjoint files and may run as concurrent branches; wave 3 (219→207→209→208) and wave 4 (217) are serialized. Merge-and-rebase each analytics issue before starting the next.
